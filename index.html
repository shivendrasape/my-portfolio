HOW I THINK ABOUT SYSTEMS

Principles I Actually Build With

Real architectural trade-offs learned from 9 years of shipping systems under live load.

Modular by Design, Not by Accident

“Most backend systems break at the boundary between teams — not because code is bad, but because the architecture never enforced the boundary.”

I architect with Spring Modulith and Domain-Driven Design so boundaries are strictly checked at compile and test time. This yields microservice-level domain autonomy with monolith-level deployment simplicity and zero multi-tenant data bleed.

Built for What Production Actually Sends

“A system that works in staging and falls apart under real Kafka lag or a burst of concurrent trades isn't ready.”

I build asynchronous-first architectures. Whether it's Kafka consumer groups handling volatile market data, Spring State Machine deterministically governing borrow trades, or dead-letter queues isolating poison pills, I design for runtime realities.

AI as Architecture, Not an API Add-On

“Most teams bolt on a prompt. I design systems where intelligence is a first-class architectural component.”

I engineer agentic systems through Model Context Protocol (MCP) servers, multi-stage RAG pipelines, Claude API, and Google ADK (Java). Agents have bounded tools, deterministic state verification, and auditability rather than unconstrained black-box executions.

01

Define Boundaries First
